This document will guide you through the compiling process. QUsb2Snes can be built with Qt 5.8 minimum but
we recommend using Qt 6.5 or higher.

== Submodules

If you get the source code with a `git clone`, you need to set up the git submodules.

[source, bash]
----
git submodule init
git submodule update
----

== Linux

=== Prerequisites

* You need the development files for Qt
* You will need the development files for websocket and serialport libraries that goes with your Qt version
* You can either use the Qbs build tool or the regular qmake build too to build it. QMake is simpler to use.

=== Compiling the GUI version (default)

[source,bash]
----
qmake QUsb2snes.pro CONFIG+='release'
make
----

Then, start the QUsb2Snes binary directory that is created.

=== Compiling without GUI

If you want to build a version that does not use a Gui (to use it without a XServer):

[source,bash]
----
qmake "QUSB2SNES_NOGUI=1" CONFIG+='release'
make
----

=== Compiling for installing

QUsb2snes will compile by default in a standalone mode where the config file is set on its current directory.
You need to use the `sqpackager_unix_installer.sh` script that will set all the proper things and install all the related files
like the localizations, desktop and man according to the specified prefix
[source,bash]
----
sh ./sqpackager_unix_installer.sh --build --install --prefix /usr/local/
----

If you need to specify which qmake version to use you can use the `--qmake-cmd` argument

== Windows

* Install Qt 6 
* Open the `.qbs` file with QCreator

== MacOS

These steps produce a native build (the resulting binary matches the architecture
of the Qt you build against: arm64 on Apple Silicon, x86_64 on Intel).

=== Prerequisites

* Xcode (or the Command Line Tools) for the clang toolchain
* Qt 6 with the websockets, serialport and svg modules. The simplest way is Homebrew,
  which ships a native build for your CPU. Install just the modules this project needs:

[source,bash]
----
brew install qtbase qtsvg qtwebsockets qtserialport
----

`qtbase` provides `qmake` and `macdeployqt`. To keep the commands below unambiguous,
point `$QTBIN` at it:

[source,bash]
----
export QTBIN="$(brew --prefix qtbase)/bin"
----

The rest of this guide uses `$QTBIN/qmake` and `$QTBIN/macdeployqt`.

=== Compiling

[source,bash]
----
git submodule update --init --recursive
mkdir build && cd build
$QTBIN/qmake ../QUsb2snes.pro CONFIG+=release CONFIG+=c++17 "QT+=svg" \
  "QMAKE_CXXFLAGS+=-U__cpp_static_assert -Wno-builtin-macro-redefined"
make -j$(sysctl -n hw.ncpu)
----

This creates `QUsb2Snes.app` inside the build directory. At this point the app links
against the Qt frameworks of your Qt install, so it only runs on a machine that has
that same Qt available.

The extra qmake arguments pass the C++17 standard, pull in the SVG module (so
`macdeployqt` bundles the SVG image plugin), and work around Apple clang defining
`__cpp_static_assert` in older language modes.

NOTE: When building with a newer Xcode SDK than the one Qt was tested with, qmake
prints an "unsupported configuration" warning. Add `CONFIG+=sdk_no_version_check` to
silence it.

=== Making a standalone, distributable .app

Use `macdeployqt` to copy the Qt frameworks and plugins into the bundle, then re-sign
it. The re-signing step is required: `macdeployqt` rewrites the embedded libraries,
which invalidates their code signatures, and on Apple Silicon macOS kills any binary
with an invalid signature (the app would crash on launch with signal 9 / exit 137).

[source,bash]
----
$QTBIN/macdeployqt QUsb2Snes.app
codesign --force --deep --sign - QUsb2Snes.app
----

Replace `--sign -` (ad-hoc) with your Developer ID identity if you intend to
distribute and notarize the app.

NOTE: Qt 6's `macdeployqt` runs an ad-hoc codesign itself at the end and may print
`codesign` errors (e.g. about the `apps/` files added below). The deployment still
completes; the explicit `codesign --force --deep` line is what produces the final valid
signature.

=== Embedding the QFile2Snes companion app

QFile2Snes (the file explorer) is shipped inside the QUsb2Snes bundle and shares its
Qt frameworks, so it shows up in the *Applications* menu. Build it, drop its binary in
`Contents/MacOS/`, register it under `Contents/MacOS/apps/QFile2Snes/`, then run a
single `macdeployqt` that fixes both executables before signing.

[source,bash]
----
# build QFile2Snes (native, same flags)
mkdir QFile2Snes/build && cd QFile2Snes/build
$QTBIN/qmake ../QFile2Snes.pro CONFIG+=release CONFIG+=c++17
make -j$(sysctl -n hw.ncpu)
cd ../..

# embed it into the already-built (but not yet deployed) QUsb2Snes.app
cp QFile2Snes/build/QFile2Snes.app/Contents/MacOS/QFile2Snes build/QUsb2Snes.app/Contents/MacOS/
mkdir -p build/QUsb2Snes.app/Contents/MacOS/apps/QFile2Snes
cp QFile2Snes/qusb2snesapposx.json build/QUsb2Snes.app/Contents/MacOS/apps/QFile2Snes/qusb2snesapp.json
cp QFile2Snes/icon50x50.png build/QUsb2Snes.app/Contents/MacOS/apps/QFile2Snes/icone.png

# deploy once (fixes the QFile2Snes binary too), then sign the whole bundle
$QTBIN/macdeployqt build/QUsb2Snes.app -executable=build/QUsb2Snes.app/Contents/MacOS/QFile2Snes
codesign --force --deep --sign - build/QUsb2Snes.app
----

NOTE: register it with `qusb2snesapposx.json` (executable `../../QFile2Snes`), copied in
as `qusb2snesapp.json`. The non-osx `qusb2snesapp.json` points at `QFile2Snes` relative
to the `apps/QFile2Snes/` folder, which is the Windows layout, not the `.app` one.
